# Docs style guide

Write CmdWarden docs in the style of the
[Google developer documentation style guide](https://developers.google.com/style).

## Reader

Write to the reader as "you".

Use the active voice.

When a step depends on a condition, write the condition first.

## Headings

Use sentence case. Capitalize the first word and the proper nouns.

Use one H1 in a file. Do not skip a heading level.

Do not start a heading with a section number such as `1.` or `UC16`.

A version heading such as `0.12.0` names a release. It is not a section number.

Do not put a link in a heading.

## Lists

Use a numbered list for a sequence of steps.

Use a bullet list for every other list.

## UI labels and code

Use bold only for a UI label, such as **Deny**, **Allow for session**, or **Start Menu**.

Use code font for a command, a path, and a file name.

## Links

Write link text that names the target.

Do not use "here" or "click here" as the link text.

A raw `http` or `https` address is allowed only in these places:

- A fenced command
- A code span
- A quoted social post that a person pastes

## Dates

Spell the month and include the year, such as November 4, 2026.
